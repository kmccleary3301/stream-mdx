# Deployment and Security

This guide covers a production deployment pattern for StreamMDX with strict CSP, hosted worker assets, and controlled HTML rendering.

## Recommended production topology

1. Build your app and StreamMDX worker bundle in CI.
2. Copy `markdown-worker.js` into static assets.
3. Serve docs/app pages and worker from the same origin.
4. Keep CSP strict (`worker-src 'self'`) and avoid `blob:`.

```bash
mkdir -p public/workers
cp node_modules/@stream-mdx/worker/dist/hosted/markdown-worker.js public/workers/markdown-worker.js
```

Then reference it explicitly:

```tsx
<StreamingMarkdown worker="/workers/markdown-worker.js" />
```

## CSP baseline

A conservative baseline for most deployments:

```text
default-src 'self';
script-src 'self';
style-src 'self' 'unsafe-inline';
img-src 'self' data: https:;
worker-src 'self';
connect-src 'self' https:;
```

Notes:

- `style-src 'unsafe-inline'` is often needed for runtime style injection in UI stacks.
- If your stack supports nonce-based styles, prefer nonce over unrestricted inline styles.

## HTML rendering policy

StreamMDX applies sanitization for untrusted HTML by default. Keep that enabled unless your input source is fully trusted and audited.

Operational policy:

- Enable `features.html` only when required.
- Prefer render-layer overrides (`htmlElements`) over sanitizer allowlist expansion.
- Review any allowlist changes as security-sensitive changes.

## MDX policy

MDX is code execution by design. Treat MDX input as trusted content unless you have a hardened compilation boundary.

- For user-generated content, keep `features.mdx` disabled.
- For trusted editorial content, enforce review + snapshot tests before publish.

## Sandboxed agent artifacts and code renderers

When streaming content generated by AI agents, LLMs, or untrusted external users, you must maintain strict isolation between the host application DOM and dynamic output. An executable reference implementation is available at [`/showcase/assistant-stream`](/showcase/assistant-stream).

### Safe defaults for agent content

1. **Disable MDX (`features.mdx: false`)**: MDX compiles into executable React components in the host document. Untrusted agent output with MDX enabled can execute arbitrary client-side code (XSS/RCE). Keep `features.mdx: false` for all agent feeds.
2. **Disable raw HTML (`features.html: false`)**: Prevent unsandboxed HTML injection into the application container.
3. **Enable link safety (`linkSafety: { enabled: true }`)**: All outbound links in markdown prose and enclosed artifacts are intercepted before opening, prompting users with a confirmation modal and dropping unsafe protocols (`javascript:`, `data:`).

### Sandbox restrictions with ArtifactFrame

Interactive visualizations and dashboards generated by agents must be sandboxed using `ArtifactFrame` (mapped to fence languages such as ````html-artifact```` or ````artifact````):

- **Iframe sandbox**: Mounts `<iframe sandbox="allow-scripts" srcdoc="...">` without `allow-same-origin`. The script execution context has no access to the parent window, cookies, `localStorage`, `sessionStorage`, or host DOM nodes.
- **Strict CSP baseline**: The embedded `srcdoc` injects a strict meta policy:
  ```text
  default-src 'none';
  script-src 'unsafe-inline';
  style-src 'unsafe-inline';
  img-src data: blob:;
  font-src data:;
  connect-src 'none';
  base-uri 'none';
  form-action 'none';
  ```
  `connect-src 'none'` blocks all outgoing network traffic (`fetch`, `XMLHttpRequest`, `WebSocket`), preventing data exfiltration.
- **Self-contained content**: Artifacts must bundle their CSS and inline SVG or canvas graphics locally, without external asset fetching.
- **Streaming lifecycle**: While the block is streaming (`isFinalized === false`), `ArtifactFrame` displays the raw syntax code block. Once finalized (`isFinalized === true`), the isolated iframe mounts and auto-sizes via a postMessage height protocol.
- **Link containment**: Clicks on anchor tags within the iframe are intercepted, posted to the host window, sanitized against allowed protocols (`http:`, `https:`, `mailto:`), and passed to the host `linkSafety` handler.

### Replacing and customizing codeRenderers

StreamMDX engine-v2 allows granular code fence renderer customization via the `codeRenderers` prop. You can map specific fence languages to specialized renderers while letting standard code blocks use the default highlighter:

```tsx
import { ArtifactFrame, StreamingMarkdown, type CodeFenceRenderer } from "@stream-mdx/react";
import { MermaidBlock } from "@stream-mdx/mermaid";

const CustomMetricRenderer: CodeFenceRenderer = ({ code, language, isFinalized, renderCode }) => {
  try {
    const data = JSON.parse(code);
    return (
      <div className="metric-panel">
        <span className="badge">{isFinalized ? "Finalized" : "Streaming..."}</span>
        <pre>{JSON.stringify(data, null, 2)}</pre>
      </div>
    );
  } catch {
    return <>{renderCode}</>;
  }
};

export function AgentChatStream({ text }: { text: string }) {
  return (
    <StreamingMarkdown
      text={text}
      engine="worker" // or "main-thread"
      features={{ mdx: false, html: false, tables: true, math: true }}
      linkSafety={{ enabled: true }}
      codeRenderers={{
        mermaid: MermaidBlock,
        "html-artifact": ArtifactFrame,
        artifact: ArtifactFrame,
        metric: CustomMetricRenderer,
      }}
    />
  );
}
```

## Release hardening checklist

- [ ] Hosted worker copied to static path and versioned with app deploy.
- [ ] CSP validated in production response headers.
- [ ] `features.html` and `features.mdx` configured intentionally (not accidental defaults).
- [ ] Regression snapshots updated and reviewed.
- [ ] Perf harness run attached to release notes.

## Incident response quick path

If a production issue appears in rendered output:

1. Disable risky feature flag (`html` or `mdx`) first.
2. Roll back to previous worker bundle + app release.
3. Compare regression snapshots to isolate the rendering delta.
4. Patch and redeploy with a new snapshot/perf report.
