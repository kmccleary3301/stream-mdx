Build the public `@stream-mdx/worker/engine` entry for the worker realm: the complete MDX compile pipeline (`@mdx-js/mdx`, `remark-gfm`, `remark-math`, `rehype-slug`, `rehype-katex`) is bundled with the DOM-free `decode-named-character-reference` decoder and `hast-util-from-html-isomorphic` parser variants. Bundling the whole pipeline also keeps require()-based (CJS) consumers on esbuild-compiled bindings instead of ESM interop wrappers, which previously reached unified as an empty preset. Custom worker entries bundled with a browser-targeted bundler — including the documented `npx esbuild markdown-worker.ts --bundle --platform=browser --format=iife` command — now boot inside a Worker without `document` or `DOMParser` and emit `INITIALIZED`/`PATCH`/`FINALIZED`, including worker-mode MDX compilation. Previously browser resolution elected `decode-named-character-reference/index.dom.js`, which threw `ReferenceError: document is not defined` before any message was handled. No consumer alias, shim, or additional configuration is required. MDX development-mode selection reads `process.env.NODE_ENV` at runtime; a browser-targeted build-time substitution previously forced development output for every consumer of the worker entry. The hosted worker bundle resolves the same DOM-free variants instead of decoding entities through the worker DOM stub.

Remove obsolete ambient `document` and `DOMParser` stubs. Public worker/direct/React imports no longer install incomplete browser globals in Node SSR; actual worker MDX compilation uses the existing DOM-free dependency variants. Bundle the same complete native MDX pipeline for the public direct/compiler entries. ESM and CJS direct compilation decode entities and compile component, math, and nested code content without DOM globals or ESM-plugin namespace wrappers reaching unified as empty presets. Resolve browser-safe MDX dependency variants for public runtime/direct/compiler bundles, while building native `node` exports separately. Vite clients no longer receive vfile's Node `path`/`process`/`url` imports; all ESM/CJS/DTS output names stay unchanged, and the shared output directory is cleaned once before either build begins.
