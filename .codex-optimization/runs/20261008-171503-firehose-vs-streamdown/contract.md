# Contract: firehose streaming vs Streamdown

- Goal: lower main-thread cost than Streamdown when very long, full-feature markdown streams at 5k-20k chars/s, with identical rendered semantics.
- Primary metric: median CDP main-thread `TaskDuration` over 3 measured streams after 1 unreported warmup (`scripts/perf/run-perf-harness.ts --runs 3 --warmup 1 --timeout 900000`).
- Guardrails: rAF delta p95, long-task p95, peak JS heap, time to first committed content, stream duration.
- Validity: minified production docs build, AC power (recorded per run in `summary.txt`), canonical semantic records SHA-256 identical between the compared runs. A different hash blocks a speed claim unless the difference is an intended correctness fix and is characterized.
- Workload:
  - `code-huge` (16.5 KB, one `js` fence)
  - `stress-mega` (253 KB) and `stress-mega-footnotes` (255 KB): headings, nested lists, task lists, tables, fenced code in several languages, inline and display math, blockquotes, links, inline HTML, footnotes. Generated by `scripts/perf/generate-stress-fixtures.ts` (deterministic).
  - `stress-xl` (1 MB): the same feature mix.
  - Scenarios `S7_firehose_5k`, `S8_firehose_10k`, `S9_firehose_20k`.
- Renderers: StreamMDX (this tree, served on :3013), StreamMDX before (`1669abb` packages with the same harness and fixtures, served on :3014), Streamdown 2.7.0 (:3013).
- Must not drift: markdown rendering correctness, streaming worker behavior, release/build, public entry points.
